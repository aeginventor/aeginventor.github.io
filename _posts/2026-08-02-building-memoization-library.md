## 시작하며

첫 번째 글인 **Why Memoization Library?**에서는 이 블로그를 시작하게 된 이유와 앞으로 어떤 기록을 남기고 싶은지 이야기했다.

이번 글에서는 그 생각을 실제 블로그로 구현하기까지의 과정을 기록하려고 한다.

블로그를 만드는 과정 역시 하나의 프로젝트였고, 앞으로 이 블로그가 어떻게 발전해 나갈지 되돌아볼 수 있는 첫 번째 개발 기록이기도 하다.

---

# 왜 GitHub Pages인가?

블로그를 만들기 전에 여러 플랫폼을 고민했다.

- Velog
- Tistory
- Medium
- GitHub Pages

결국 GitHub Pages를 선택한 이유는 단순했다.

**블로그도 하나의 프로젝트처럼 관리하고 싶었기 때문이다.**

Git으로 버전을 관리할 수 있고,

직접 구조를 수정할 수 있으며,

무엇보다 개발자로서 가장 자연스러운 방식이라고 생각했다.

---

# Academic Pages를 선택한 이유

처음부터 Jekyll 블로그를 직접 만드는 방법도 있었다.

하지만 처음부터 모든 구조를 설계하기보다는,

이미 잘 만들어진 기반 위에서 내가 원하는 모습으로 바꿔 나가는 것이 더 효율적이라고 판단했다.

그래서 Academic Pages를 선택했다.

하지만 이름 그대로 Academic Pages는 연구자 포트폴리오를 위한 템플릿이었다.

논문, 발표, 연구 이력 중심의 구조는 내가 만들고 싶은 블로그와는 거리가 있었다.

그래서 이 템플릿을 그대로 사용하는 대신,

내 기록 방식에 맞는 개발 블로그로 하나씩 바꾸기 시작했다.

---

# 가장 먼저 바꾼 것

## 사이트의 정체성

가장 먼저 수정한 것은 `_config.yml`이었다.

사이트 이름과 설명, 프로필 정보를 내 블로그에 맞게 변경했다.

블로그의 이름은 이미 정해져 있었다.

> Memoization Library

첫 번째 글에서 이야기했듯,

배운 것과 경험한 것을 다시 꺼내 사용할 수 있는 공간이라는 의미를 담고 있다.

---

## 홈 화면

기본 홈 화면에는 Academic Pages를 소개하는 내용이 그대로 남아 있었다.

그래서 블로그를 처음 방문한 사람이

"이 블로그는 어떤 곳인가"

를 바로 이해할 수 있도록 홈 화면을 새롭게 구성했다.

---

## About

기존에는 Home과 About이 사실상 같은 페이지였다.

이를 분리하여,

Home은 블로그를 소개하는 공간으로,

About은 나를 소개하는 공간으로 정리했다.

---

# 메뉴도 다시 설계했다

Academic Pages의 기본 메뉴는 다음과 같았다.

- Publications
- Talks
- Teaching
- Portfolio

하지만 내가 남기려는 기록과는 맞지 않았다.

그래서 블로그의 목적에 맞게 메뉴를 다시 설계했다.

| 메뉴 | 의미 |
|------|------|
| Journal | 경험과 생각, 회고 |
| Notes | 새롭게 이해한 개념 |
| Solutions | 문제 해결 과정 |
| Projects | 프로젝트 기록 |

이렇게 구분한 이유는

**글을 쓰기 전에 스스로 "이 글은 무엇을 남기기 위한 기록인가?"를 먼저 생각하기 위해서**이다.

앞으로도 이 기준은 계속 유지하려고 한다.

---

# 디자인도 기록의 일부라고 생각했다

블로그는 단순히 글을 올리는 공간이 아니라

하나의 프로젝트이기도 하다.

그래서

- 프로필 이미지
- 파비콘
- 홈 화면
- 메뉴 구조

까지 모두 조금씩 손보며

Memoization Library만의 모습을 만들어가고 있다.

아직 완성은 아니지만,

기록이 쌓일수록 이 공간도 함께 성장할 것이라고 생각한다.
